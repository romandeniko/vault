1) **Появление идеи:** формулировка основно концепции будущего приложения.
	**Роль аналитика:** придумать идею для приложения:
	`"Приложение должно позволять пользователям заказывать еду из ресторанов с возможностью отслеживания доставки в реальном времени. Основная аудитория — жители городов 20-45 лет."`
2) **Анализ рынка**: исследование потребностей, конкурентных решений и рыночных тенденций.
	**Роль аналитика**: аналитик составляет сравнительную таблицу конкурентов.
	`"У конкурентов нет функции предзаказа на неделю вперед. Это может стать нашим преимуществом."`
3) **Реализация**: проектирование, разработка, тестирование
	**Роль аналитика**: пишет спецификацию для функции оплаты.
	`"Пользователь должен иметь возможность оплатить заказ через Apple Pay, Google Pay или банковскую карту. При неудачной оплате система предлагает повторить попытку или выбрать другой метод."`
4) **Релиз**
	**Роль аналитика**: предлагает доработать процесс после получения результатов эксплуатации.
	`"Упростить форму ввода данных карты: добавить сканирование через камеру."`
5) **Поддержка и развитие**
	**Роль аналитика**: предлагает добавить чат с поддержкой исходя из жалоб пользователей.
	`"60% обращений в службу поддержки — вопросы по статусу заказа. Чат снизит нагрузку на операторов."`
6) **Завершение**: снятие продукта с поддержки и вывод из эксплуатации по причине утраты актуальности или исчерпания ресурсов.
	**Роль аналитика**: составить отчет о закрытии устаревшео приложения
	`"Приложение для доставки еды 2015 года больше не поддерживается из-за устаревшего кода и высокой конкуренции. Рекомендуется перенаправить пользователей на новую версию с AI-рекомендациями."`
