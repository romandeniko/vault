Транзакция — это последовательность операций с базой данных, которые выполняются как единое целое.

Гарантирует, что либо все операции выполняться успешно, либо ни одна из них.

### Блокировка

Метод ограничения доступа к данным для обеспечения корректной обработки транзакций. 
Используется сервером для ограничения доступа к данным: пока одна транзакция обращается к данным, другая заблокирована.

#### Гранулярность

Существует несколько стратегий блокировки:
* блокировка таблиц: не позволяет нескольким пользователям одновременно менять данные в одной таблице. Требует небольшого времени, но может привести к большому времени ожидания при большом кол-ве пользователей;
* блокировка страниц: не позволяет нескольким пользователям одновременно менять данные  на одной и той же странице (от 2 до 16 кБ) таблицы;
* блокировка строк: не позволяет нескольким пользователям одновременно менять одну и ту же строку таблицы. Требует большого количества операций, но позволяет нескольким пользователям работать с одной и той же таблицей, если они работают с разными строками;

PostgreSQL: многоверсионное управление конкурентностью + блокировка строк по умолчанию.

#### Создание транзакций

```sql
-- Начало транзакции
BEGIN;

-- Проверка баланса с использованием условия в WHERE
-- Списываем деньги, только если баланс достаточный
UPDATE accounts
SET user_balance = user_balance - 1000
WHERE user_id = 1
  AND user_balance >= 1000;

-- Проверяем, что операция прошла успешно
-- В реальном приложении проверяется количество обновленных строк
-- Если 0 строк обновлено - недостаточно средств, нужен ROLLBACK

-- Зачисляем деньги получателю (если он существует)
UPDATE accounts
SET user_balance = user_balance + 1000
WHERE user_id = 2;

-- Применение изменений (или ROLLBACK при ошибке в коде приложения)
COMMIT;
```

* Каждая явная транзакция начинается с использования оператора **BEGIN** или **START TRANSACTION**;
* Команда завершается:
	* **COMMIT**: пометить изменения как постоянные и освободить все ресурсы (снять блокировки);
	* **ROLLABACK:** вернуть данные в состояние до начала транзакции, ресурсы также освобождаются;

#### Точки сохранения транзакции 

Позволяют откатится к конкретной точке транзакции, а не к ее началу.

```sql
SAVEPOINT my_savepoint;
```

Для отката используются команды **ROLLBACK** и **TO SAVEPOINT**.

```sql
BEGIN;

-- Создаем точку сохранения перед изменением баланса первого пользователя
SAVEPOINT before_updating_user_1;
UPDATE accounts SET balance = balance + 100 WHERE user_id = 1;

-- Проверка условия для первого пользователя
-- например, проверяем логику бизнес-правил

-- Здесь мы предполагаем, что условие не выполнилось, и нам нужно отменить изменение баланса
ROLLBACK TO SAVEPOINT before_updating_user_1;

-- Обновляем баланс для второго пользователя
UPDATE accounts SET balance = balance + 200 WHERE user_id = 2;

-- Завершаем транзакцию
COMMIT;
```
